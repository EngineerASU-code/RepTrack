# RepTrack — ТЗ на визуально готовое Android-приложение

Версия 1.0 · 16 ноября 2026 · статус: задание на реализацию, не отчёт о выполнении.

## 1. Результат и границы

Переработать представление существующего Android-приложения так, чтобы оно воспроизводило утверждённый концепт из `design/`: композицию, плотность, иерархию текста, изображения упражнений, анатомические иллюстрации, таблицы подходов, графики, таймер и навигацию. Одной смены палитры и скругления стандартных Material-карточек недостаточно.

Рабочая логика, сохранённые профили, история и расчёты сохраняются. Разработка Telegram, доставки, облака и новых функций обмена заморожена. Существующие операции с данными остаются доступными во вторичной группе настроек; заморозка не означает удаление данных или кода. Веб-прототип не является результатом этого задания: принимается APK на Android.

Этот документ — основной источник требований **к визуалу и навигации**. Единый промпт остаётся источником продуктовой логики. При конфликте: последняя явная инструкция пользователя → этот документ → целевые PNG согласно таблице ниже → старые описания и текущий интерфейс. Существующая реализация и старые preview не являются визуальным эталоном.

Полное соответствие означает соответствие всем применимым пунктам и контрольным кадрам, а не буквальное копирование презентационных рамок телефона, ошибок текста или демонстрационных результатов.

Разрешённые и обязательные адаптации:

1. Лаймовый акцент R02–R06 переводится в Purple Pro; структура и графика сохраняются. Другие темы меняют цвета, а не компоновку.
2. «Тоннаж», «объём» как сумма кг × повторения отсутствуют в UI. На их месте в сетке R05 — «Рабочие подходы», без единицы кг. Остаются «Макс. вес», «Повторы», «e1RM». Это сознательное отличие по требованию пользователя.
3. Основной вариант упражнения из R01: **«Подходы · Техника · Мышцы»**, а не прежнее «Сводка · Техника · Мышцы». История/прогресс доступны из карточек и экрана прогресса, без второго конкурирующего ряда вкладок R04.
4. Фотография техники, подробные таблицы и парные карточки R04 сохраняются внутри соответствующих вкладок. Не складывать две альтернативные композиции целиком в одну длинную страницу.
5. Android использует настоящие системные status/navigation bars и safe insets. Рамки устройства, Dynamic Island, часы и батарея из PNG не рисуются внутри приложения.
6. Числа, даты, имена упражнений и техника на концептах не являются подтверждёнными пользовательскими данными. Для визуального сравнения используется отдельный демонстрационный профиль.
7. Не добавлять неработающие колокольчики, закладки, облачные переключатели и настройки плотности ради сходства. Если функционального действия нет — убрать кнопку, сохранив баланс шапки; перечень таких исключений включить в отчёт.

## 3. Система размеров и стиля

Ниже — нормативные значения для реализации, а не утверждение о точном извлечении пикселей из PNG. Отступление допустимо только для устранения подтверждённого расхождения на сравнении; новое значение фиксируется единообразно в токенах.

| Поверхность / поднятая / поле | `#211C31` / `#2D2540` / `#191522` |
| Акцент / светлый акцент | `#8957F6` / `#B4A0FF` |
| Текст основной / вторичный | `#F7F5FC` / `#A9A3B9` |

| Градиент CTA | от `#8957F6` к `#B05AFF`; читаемый контраст текста проверяется на обоих концах |
| Шаг отступов | 4 dp; основные значения 4/8/12/16/20/24/32 |
| Поля экрана | 16 dp, на широком телефоне 20 dp; зазор карточек 12 dp |
| Радиусы | карточка 16 dp; поле 10 dp; CTA 14 dp; сегмент/чип 12 dp; круглые кнопки 50% |
| Шапка / нижняя панель | 56 dp / 64 dp без системных inset; нижняя панель может вырасти до 72 dp для подписей |
| Кнопка основная | 48–52 dp высотой, на ширину контейнера |
| Область нажатия | минимум 48 × 48 dp; видимая иконка 22–24 dp |
| Изображение в строке | 48–56 dp; одинаковый масштаб и фон внутри списка |
| Таблица подходов | строка 48–52 dp; заголовок 32–36 dp; поле 40–44 dp с областью нажатия 48 dp |

Шрифт: семейство Roboto с кириллицей; основной 14–16 sp, подпись 12–13 sp, заголовок карточки 16–18 sp/600–700, заголовок экрана 28–32 sp/700, число рекорда 28–32 sp/700. Цифры в таблице и таймере — табличные. Не использовать моноширинный шрифт во всём интерфейсе. Подписи не делать тонкими и малоконтрастными ради сходства с изображением.

Иконки: один векторный набор с одинаковым штрихом около 1,8–2 dp, скруглёнными концами и оптическим размером. Запрещены Unicode-глифы и emoji вместо иконок. Предпочтительны готовые векторы Material Symbols подходящего начертания либо оригинальные SVG/VectorDrawable. Генерация растровых иконок навигации не нужна. Логотип RepTrack — отдельный аккуратный знак гантели/буквы из R01, не обычный текстовый символ.

Material 3 используется как техническая основа: его стандартная крупная плашка выбранной вкладки, высота полей и диалогов не задают внешний вид. Для соответствия переопределить размеры, цвета и формы общих компонентов. Динамические цвета Android не переопределяют выбранную тему приложения.

## 4. Навигация и контекст

Корневые разделы в постоянном порядке: **Главная · Зал · План · Прогресс · История**. Равная ширина пяти элементов, подпись под иконкой, выбранный элемент подсвечивается акцентом. Никакого переноса панели наверх или горизонтальной прокрутки пяти разделов. Компактное выделение, как R01; не крупная стандартная капсула Material.

Шапка корня: знак + RepTrack слева, настройки справа. Активный профиль доступен через компактный селектор/подзаголовок; длинное имя не вытесняет бренд и настройки. У импортированного демонстрационного профиля есть метка «Демо». При тренировке шапка меняется на Back, название дня, длительность и меню. Настройки открываются отдельным экраном, а не шестой вкладкой.

Активная тренировка и полноэкранное упражнение — вложенные экраны со скрытой нижней панелью. Back возвращает в прежний раздел, позицию списка и выбранное упражнение; сессия продолжает сохраняться. Возврат не завершает и не отменяет тренировку. На главной и в «Зале» есть явная кнопка «Продолжить», если сессия активна. Завершение и отмена требуют разных действий.

Каталог доступен из «Зала», выбор упражнения в прогрессе использует тот же визуальный список. Экран упражнения вызывается из тренировки, каталога, прогресса и истории. Источник определяет действие Back. Вне активной сессии вкладка «Подходы» показывает последнее выполнение только для чтения и действие «Начать тренировку»; не создаёт подходы в истории.

Переключение корней сохраняет локальные фильтры и прокрутку. При переходе в исходную сессию из графика сохраняются упражнение, метрика и период. Использовать один стек переходов; не вложенные независимые модальные окна для полноценных экранов.

## 5. Экранные требования

### S01 — Главная

Порядок строго по R01/R02:

1. Компактная фирменная шапка.
2. Карточка «Следующая тренировка»: название дня крупно, целевые группы вторично, справа объёмный оригинальный знак/предметная иллюстрация. Рендер не заменяет текст и не занимает отдельный большой блок.
3. Основная кнопка «Начать тренировку» с маленькой иконкой Play; при активной сессии «Продолжить тренировку».
4. Тонкий разделитель; заголовок «Цикл»; чипы дней в одну строку. Выполненный — галочка, текущий — акцентный контур/фон, будущие — спокойные. Для длинного цикла допустима прокрутка только чипов.
5. Карточка последней тренировки: название, дата, компактные фактические показатели, стрелка перехода.
6. Карточка «Прогресс: [упражнение]»: реальный мини-график с точками и полупрозрачной заливкой, значение/изменение, действие открытия полного графика.

На контрольном телефоне 412 × 915 dp без увеличения шрифта видны шапка, старт, цикл, последняя сессия и минимум заголовок + основная область мини-графика. Нельзя тратить первый экран на служебный текст о хранении, огромные пустые карточки или список всех шаблонов. На 360 × 800 допустима прокрутка к низу графика. Выбор упражнения мини-графика сохраняется; первоначально выбрать упражнение с минимум двумя точками, при отсутствии такого честно показать одну точку/пустое состояние.

### S02 — Зал без активной сессии

Сверху компактная карточка рекомендованного дня со стартом, затем другие дни и строка каталога. Не повторять одинаковые большие кнопки «Начать» на нескольких высоких пустых карточках. День: миниатюра/группы, название, число упражнений, одно действие. Дубликаты импортированных планов различимы названием и контекстом; эта задача не меняет правила импорта.

### S03 — Активная тренировка

Композиция R01/R03: Back + название + таймер длительности; ниже две подписи «Упражнения 2/6», «Подходы 7/18» и тонкая полоса прогресса. Значения только из фактических состояний; завершённое и пропущенное различимы.

Список компактных accordion-карточек. Свёрнутая: миниатюра с целевой группой, название 16 sp bold, группа мышц вторично, chevron. Текущее упражнение имеет акцентную границу и мягкий tint. Раскрытая карточка содержит прошлое выполнение, таблицу и действие деталей. По умолчанию раскрыто текущее упражнение; открытие другого не удаляет введённое. Безопасно допускаются несколько раскрытых, но не все автоматически.

Таблица: «№ | Вес, кг | Повторы | ✓». Разминка отмечена компактным «Р», рабочие строки пронумерованы. Поля короткие и выровнены по колонкам. Выполнено — заполненный круг с галочкой; не выполнено — контур; текущая строка — слабый фон акцента. Удаление/замена/пропуск — в меню строки/упражнения, не ряд длинных кнопок под каждым подходом. «Добавить подход» — компактная вторичная кнопка в ширину таблицы.

«Завершить тренировку» закреплена в нижней зоне над системным inset. Во время отдыха там компактная панель «Отдых 01:30» с паузой/продолжением и пропуском; завершение остаётся доступно через явную кнопку/расширение панели без прокрутки всего журнала. Панель не закрывает последнюю строку: список имеет нижний padding по её высоте.

Числовая клавиатура: десятичная для веса, целая для повторов; выбранная строка прокручивается выше IME. Увеличение длительности/таймера не перестраивает ширины. Завершение показывает короткий итог с показателями и возвратом на главную/историю в том же стиле.

### S04 — Полноэкранное упражнение, «Подходы»

Back, название, только рабочие вторичные действия; ниже сегменты **Подходы / Техника / Мышцы**. Это полноценный экран, не 90%-диалог с кнопкой «Закрыть».

Верх контента — крупная иллюстрация движения/тренажёра с выделенными целевыми группами, как R01. Затем компактная карточка прошлого выполнения с датой и последовательностью подходов; ниже таблица текущих подходов из S03. Внизу — добавление подхода и панель отдыха. При длинном содержимом медиа прокручивается, таблица остаётся достижимой без вложенного скролла.

Карточки «Прошлый раз» и «Личный рекорд» образуют пару, как R04; на узком экране складываются вертикально. Каждая показывает реальную дату/значение и открывает исходную сессию/прогресс. Обе доступны также вне сессии, но запись подходов там заблокирована.

### S05 — Упражнение, «Техника»

Та же шапка/вкладки. Большое медиа с правильным упражнением и оборудованием: постер 16:9 или 4:3, радиус 16 dp, реальная кнопка Play только при наличии воспроизводимого материала. Далее «Техника выполнения», 3–6 коротких пронумерованных шагов с акцентными кружками; затем компактная карточка целевых мышц с миниатюрой и основной/вспомогательными группами, ссылка на S06. Источник доступен вторичным текстовым действием, не большой кнопкой вместо контента.

Анимация управляется пользователем, не зацикливается автоматически при каждом открытии. Пока доступно только фото — показывать фото без фиктивной длительности/GIF/Play. Ошибка воспроизведения сохраняет постер и даёт повтор, локальный материал работает офлайн.

### S06 — Упражнение, «Мышцы»

Подробная качественная схема тела на нейтральном тёмном фоне: передняя/задняя проекции рядом либо переключаемые на узком телефоне. Основные мышцы — акцент, вспомогательные — более слабая заливка/штриховка; легенда повторяет различие словами. Чёткие границы анатомических групп, пропорции и ориентация, без безликой пиктограммы человека. Ниже названия групп и роль. Мышцы и оборудование должны соответствовать конкретному варианту упражнения, а не угадываться по похожему названию.

### S07 — План

По R06: шапка с названием/редактированием программы; горизонтальный цикл дней; выбранный день; компактные параметры включения в цикл; строки упражнений с миниатюрой, названием, группой и сводкой плана. Ручка перестановки — у края, меню отдельно. Добавление упражнения — одна понятная вторичная кнопка внизу списка.

Параметры подходов редактируются в компактной форме с единицами и подписями; редактор не занимает половину экрана служебным текстом. Сохранение/отмена ясно отделены; уход с несохранёнными изменениями обрабатывается. Меню программы содержит переименование/копию/удаление; экспорт остаётся вторичным, не конкурирует с тренировкой. Для функций без точного макета применять токены и компоненты основной композиции, не вводить отдельный стиль.

### S08 — Каталог и поиск упражнения

Полноэкранный список: поиск, компактные фильтры группы/оборудования, строки 64–80 dp с одинаковыми миниатюрами, названием и вторичной подписью. Чекбоксы при множественном выборе для плана; отдельное открытие деталей не должно случайно добавлять упражнение. В поиске различать отсутствие результата и отсутствие каталога. Сохранить исходные названия импортированных упражнений, неоднозначные варианты помечать как требующие уточнения.

### S09 — Прогресс

По R05, переведённому в Purple Pro: заголовок/краткая подпись → карточка выбранного упражнения с изображением тренажёра и группой → ряд метрик → большая карточка графика с итоговым значением и изменением → выбор периода → «Личные рекорды» 2 × 2 → последние исходные тренировки.

Метрики: **Макс. вес / Повторы / e1RM**. Четвёртую пустую вкладку ради сходства не рисовать. Четыре карточки: «Макс. вес», «Рабочие подходы», «Повторы», «e1RM (оценка)». Для счётчиков явно указывать, например, «за выбранный период»; у рекорда — дату исходного результата. Не называть суммарное число подходов личным рекордом: в общей сетке это «За период», рядом с собственно рекордами.

График: высота области построения 180–220 dp, ось Y со значениями и единицами, ось X с читаемыми датами, тонкая сетка, линия 2–3 dp, точки 5–6 dp, мягкая заливка под линией. Временные интервалы на X пропорциональны времени, не просто номеру записи. Линия не выходит за plot bounds. Без сглаживания, которое создаёт ложные максимумы.

Нажатие/перетаскивание выбирает ближайшую по X реальную точку, показывает значение/дату/подход и действие «Открыть тренировку». Выбранная точка визуально выделена. Крайние tooltip не обрезаются. За период без результатов — объяснение и сброс фильтра; одна точка — один маркер без линии роста. Повторяющиеся даты обрабатываются устойчиво, исходная сессия однозначна. Правила агрегации и e1RM берутся из продуктовой логики и показываются по Info.

Периоды: «Неделя / 1 мес. / 3 мес. / Всё время», выбранное значение заметно. На узком экране контролы переносятся в два ряда либо горизонтально прокручиваются без обрезания текста. Длинный ряд дат прореживается, выбранная дата доступна в tooltip. График не подменяется декоративной линией или одинаковыми столбиками с пустыми значениями.

### S10 — История и завершённая сессия

У истории нет отдельного детального PNG: это **новая композиция на основе R05/R03**, а не заявление о существующем макете. Шапка «История», фильтр периода/поиск, группировка по месяцу; строки как нижние карточки R05: дата, название дня, фактические показатели, chevron. Деталь использует знакомые accordion-карточки и таблицу только для чтения, с итогами/комментарием. Редактирование и удаление — явные действия, не реакция на случайное нажатие числа. Пустая история предлагает начать тренировку.

### S11 — Настройки, темы, профиль

R07/R08: сгруппированные строки с иконкой слева, названием/значением, chevron или переключателем справа. Группы «Оформление», «Тренировка», «Профили», «Данные», «О приложении». Тема — экран с небольшими наглядными карточками шести схем и видимой отметкой выбора; переключение мгновенное и сохраняемое. Размеры компонентов остаются прежними.

Расширенные функции обмена не занимают первый экран настроек; существующие доступны внутри «Данные / Обмен». Не показывать обещание работающего облака или активированного Telegram без фактического состояния. Добавление профиля, длинные имена, выбранный профиль и импортированная история используют общий стиль, без технических ID на виду. Смена темы не меняет данные.

## 6. Изображения, иконки и обязательный набор материалов

Визуально готовая версия должна иметь реальные локальные материалы для **всех упражнений стартового цикла и всех однозначно сопоставленных упражнений импортированного тестового профиля**. До начала реализации составить таблицу соответствия каталог → вариант оборудования → материал. Неоднозначные названия уточняются/разделяются; до сопоставления для них допустимо честное пустое состояние, но список исключений должен быть перечислен в приёмке. Нельзя объявлять весь каталог визуально завершённым по одной иллюстрации жима ногами.

| Ресурс | Формат и минимальные требования | Назначение |
|---|---|---|
| Логотип | VectorDrawable/SVG, светлая/тёмная версии | Шапка, адаптивный Android launcher icon |
| Иконки | Вектор, общий штрих и viewBox 24 × 24 | Навигация, таблица, меню, таймер, рекорды, настройки |

| Основной рендер | WebP, длинная сторона минимум 960 px, корректный crop | Вкладка подходов, подробность упражнения |

Для каждого материала вести `design/assets-manifest.csv`: `asset_id, exercise_id, variant, role, local_path, source_url_or_generation_record, author, license, attribution, verification_status`. Этот manifest — поставка следующего этапа; в данном ТЗ не утверждается, что материалы уже получены.

Можно генерировать оригинальный декоративный знак, предметные изображения и нейтральные фотосцены. Нельзя считать сгенерированную анатомию, хват, положение суставов и траекторию проверенной техникой. Учебные изображения/тексты требуют соответствия конкретному упражнению и проверки по надёжному источнику; для них предпочтителен лицензированный каталог. Генерация допустима как заготовка, финальная приёмка техники требует отдельной проверки, а не только визуального сходства. Не копировать фотографии из чужого приложения и не встраивать скриншот телефона из концепта как интерфейс.

Для missing/error показывать оформленную заглушку с понятным текстом, без фальшивого Play и нарисованных неизвестных мышц. Заглушка допустима в исключительном/ошибочном состоянии; для обязательных эталонных кадров демонстрационного каталога это незакрытая задача.

## 7. Состояния, адаптация и доступность

Каждый экран должен иметь заполненное, пустое, длинное и ошибочное состояние; загрузка медиа — poster/skeleton без скачка размеров. Не показывать бесконечный skeleton у локально отсутствующего материала. Сообщения сохранения краткие, без постоянных технических пояснений в теле экрана.

Контрольные размеры: **360 × 800, 412 × 915 dp**, portrait; дополнительно landscape без потери управления. При ширине ≥600 dp допустима двухколоночная композиция/боковая навигация с теми же разделами; мобильный эталон не растягивается на всю ширину. Базовая приёмка — Purple Pro, font scale 1.0; устойчивость дополнительно проверяется на 1.3 и 2.0. При крупном тексте блоки растут/перестраиваются, а не обрезают значения.

Проверить gesture navigation и 3-button navigation, вырез камеры, IME, восстановление после поворота/сворачивания. Insets применяются один раз; между приложением и системой нет лишней полосы. Основная кнопка и последняя строка не перекрыты.

Обычный текст контрастен ≥4,5:1, крупный ≥3:1; значимые контролы/границы ≥3:1. Завершение подхода, основная/вспомогательная мышца, выбор темы различимы не только цветом. Иконки имеют доступные названия, поля — подписи, диаграмма — текстовое резюме и список значений для TalkBack. Поддержать reduced motion/отключённые системные анимации; переходы 150–250 мс, без обязательного свечения/параллакса.

## 9. Проверяемая приёмка

### 9.1 Набор данных

Отдельный demo-профиль: цикл Push/Legs/Pull/Up, несколько завершённых сессий за месяц с непостоянными интервалами и ростом/снижением весов, несколько упражнений, разминка/рабочие подходы, активная сессия с выполненными и незаполненными строками. Дополнительно профиль без истории, длинные русские названия и большой вес. Реальный профиль/импорт не перезаписываются. Иллюстративные значения PNG разрешены только как явно синтетическая изолированная фикстура, а не запись пользователю.

### 9.3 Метод сравнения

1. Запускать фактически собранный APK, фиксировать commit, build variant, Android API, viewport/density/font scale, тему и профиль. Скриншот веба не принимается как подтверждение Android.
2. Из исходного PNG выделить конкретный экран, исключить рамку телефона/системную область и внешние презентационные подписи. Нормализовать **равномерно**, без растяжения осей. Сопоставлять блоки и пропорции с учётом длинного контента и перечисленных отличий.
3. Для каждого Cxx составить side-by-side и 50%-overlay с исходным референсом/аннотированным целевым кадром. Для новых состояний эталон создаётся из того же набора компонентов и помечается «производное состояние», не подменяет исходный PNG.
4. Визуальная проверка обязательна: сравнить порядок/площадь блоков, плотность, размеры текста, медиа, форму иконок, таблицу и график. Автоматический pixel diff помогает между повторными APK-кадрами, но не доказывает соответствие презентационному PNG с другими данными.
5. На нормализованном базовом размере основные границы блоков не расходятся с целевым layout более чем на 4 dp, контрольные размеры компонентов — более чем на 2 dp. Исключения для текста/системных insets описываются. Токены цветов берутся из единого набора, а не подгоняются отдельно для каждой карточки.
6. Любое отсутствие обязательного фото/мышечной схемы/графика, другой порядок блоков, диалог вместо экрана, перекрытие CTA/IME или лишняя верхняя навигация — блокирующее расхождение. Незначительное отличие тени/антиалиасинга не блокирует, если композиция и читаемость соблюдены.

### 9.4 Определение готовности

- Все S01–S11 реализованы, C01–C15 представлены и проверены; нет незакрытых блокирующих визуальных расхождений.
- Обязательные упражнения имеют проверенные материалы; исключения перечислены с причинами, без скрытой подмены заглушками.
- Графики используют реальные записи активного профиля, числа и источники согласованы; тоннаж отсутствует.
- Старт → ввод → отметка подхода → отдых → техника → возврат → завершение → история → прогресс проходит в APK без потери/дублирования данных. Проверяется также восстановление активной сессии после перезапуска.
- Работают Back, фильтры, смена темы, клавиатура, TalkBack-имена; нет декоративных неработающих контролов.
- Переданы APK, исходники, manifest ассетов и краткий визуальный отчёт с контактным листом/сравнениями и командами сборки. Успешная компиляция сама по себе не закрывает визуальную приёмку.
