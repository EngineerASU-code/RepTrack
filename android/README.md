# RepTrack Android

Нативный офлайн-дневник на Kotlin, Jetpack Compose и Material 3. Структура — MVVM + Repository; локальное хранение — версионированная SQLite через `SQLiteOpenHelper`. Для записи и просмотра истории сеть не нужна.

## Stage 1

- Планы тренировок: создание, переименование, копия, удаление, порядок цикла, упражнения и плановые подходы.
- Тренировка: снимок выбранного плана, автосохранение, восстановление активной сессии, рабочие и разминочные подходы, пауза/возврат/пропуск отдыха, замена или пропуск упражнения, комментарии, раздельные завершение и отмена.
- История с датой, длительностью, снимком названия плана, выполненными подходами и комментарием. Правки шаблона не переписывают сохранённую сессию.
- Прогресс по упражнению и периоду: максимальный рабочий вес, повторы, e1RM, сравнение с предыдущим периодом и переход к исходной сессии.
- Настройки единиц, шести цветовых схем и таймера отдыха.
- Зашифрованная резервная копия дневника через Android Storage Access Framework. Импорт заменяет локальные данные только после явного подтверждения. Шаблоны планов можно отдельно экспортировать и импортировать как JSON.

### Единицы и аналитика

- Вес хранится в килограммах. При выборе `lb` значение пересчитывается только для отображения; исходная история не меняется.
- Максимальный вес — наибольший завершённый рабочий подход в завершённой тренировке. Разминка, пропуски и упражнения без силовой нагрузки исключены.
- e1RM использует формулу Эпли `вес × (1 + повторы / 30)` для 1–10 повторений и помечается как оценка.
- Приложение не вычисляет и не показывает тоннаж (`вес × повторы`).
- Неизвестные веса остаются пустыми. Вымышленные завершённые тренировки не создаются при обычном первом запуске.

### Защита и перенос данных

- Формат резервной копии версии 1: PBKDF2-HMAC-SHA256 (210 000 итераций) + AES-256-GCM со случайными солью и nonce; пароль в файл не записывается.
- Пароль резервной копии не восстанавливается приложением. Сохрани его отдельно от файла.
- Экспорт планов не содержит историю или настройки и не шифруется; импорт добавляет новые шаблоны.
- SQLite schema version 2 мигрирует версию 1 без удаления пользовательских таблиц.

## Сборка и проверки

Текущая рабочая среда: JDK 21, Android SDK API 35/36, Build Tools 36.0.0. Gradle Wrapper закреплён на 8.11.1, Java/Kotlin bytecode target — 17.

В PowerShell из папки `android/`:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\openjdk\jdk-21.0.8'
$env:ANDROID_HOME = 'C:\Program Files (x86)\Android\android-sdk'
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug
```

Для миграции SQLite и импорта/восстановления на подключённом эмуляторе:

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=app.reptrack.DiaryRepositoryInstrumentedTest
```

Для загрузки синтетических данных в тестовый Android-эмулятор (четыре сессии за последние 30 дней):

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=app.reptrack.ManualPreviewSeedTest
```

Фикстура изменяет только базу AVD, запущенного для проверки. Первичная установка на пользовательское устройство остаётся без поддельной истории.

Debug APK после сборки: `app/build/outputs/apk/debug/app-debug.apk`. Подписанный release APK и публикация не настраивались.

## Границы Stage 1

Stage 1 покрывает личный офлайн-дневник и перенос собственных резервных копий/шаблонов. Профили тренера, назначения программ подопечным, защищённый обмен между установками, backend и Telegram относятся к следующим этапам. В проект не добавлена непроверенная база упражнений, анатомические изображения или инструкции по технике.
