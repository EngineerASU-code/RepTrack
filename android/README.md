# RepTrack Android

Нативный офлайн-дневник на Kotlin, Jetpack Compose и Material 3. Структура — MVVM + Repository; локальное хранение — версионированная SQLite через `SQLiteOpenHelper`. Для записи и просмотра истории сеть не нужна.

## Stage 1

- Планы тренировок: создание, переименование, копия, удаление, порядок цикла, упражнения и плановые подходы.
- Тренировка: снимок выбранного плана, автосохранение, восстановление активной сессии, рабочие и разминочные подходы, пауза/возврат/пропуск отдыха, замена или пропуск упражнения, комментарии, раздельные завершение и отмена.
- История с датой, длительностью, снимком названия плана, выполненными подходами и комментарием. Правки шаблона не переписывают сохранённую сессию. Из истории можно повторно подготовить `.rptdelivery` для активной связи; перед ShareSheet приложение предупреждает, что PDF читаем Telegram. В зале каталог из планов и истории открывает детали упражнения до запуска сессии.
- Прогресс по упражнению и периоду: максимальный рабочий вес, повторы, e1RM, сравнение с предыдущим периодом и переход к исходной сессии.
- Настройки единиц, шести цветовых схем и таймера отдыха.
- Зашифрованная резервная копия дневника через Android Storage Access Framework. Импорт заменяет локальные данные только после явного подтверждения. Шаблоны планов можно отдельно экспортировать и импортировать как JSON.

### Единицы и аналитика

- Вес хранится в килограммах. При выборе `lb` значение пересчитывается только для отображения; исходная история не меняется.
- Максимальный вес — наибольший завершённый рабочий подход в завершённой тренировке. Разминка, пропуски и упражнения без силовой нагрузки исключены.
- e1RM использует формулу Эпли `вес × (1 + повторы / 30)` для 1–10 повторений и помечается как оценка.
- Приложение не вычисляет и не показывает тоннаж (`вес × повторы`).
- Неизвестные веса остаются пустыми. Вымышленные завершённые тренировки не создаются при обычном первом запуске.

### Защита и перенос данных

- `.rptbackup`: JSON-архив версии 4 в контейнере PBKDF2-HMAC-SHA256 (210 000 итераций) + AES-256-GCM. Соль — 16 байт, nonce — 12 байт, тег — 128 бит; пароль в файл не записывается. Чтение поддерживает архивы версий 1–4. Принятое обновление, отложенное активной тренировкой, переносится как локально разрешённое событие применения; после восстановления без ключей связи оно применяется один раз при завершении/отмене сессии. Доверенные связи и ключи не восстанавливаются.
- Пароль резервной копии не восстанавливается приложением. Сохрани его отдельно от файла.
- `.rptplan` содержит только планы и не шифруется; импорт добавляет новые шаблоны.
- Android Auto Backup выключен: зашифрованный файл копии — переносимый путь восстановления. Связи устройств и ключи обмена не входят в архив; после восстановления устройства нужно связать заново.

## Stage 2 — локальный тренерский журнал и ручной обмен

- Профили подопечных, изолированные планы, история и аналитика; независимые локальные копии назначенных программ со стабильным ID и версиями. Из выбранного профиля можно отправить его индивидуально изменённую программу; repository проверяет владельца и связь.
- Обновления показывают различия и предупреждают о локальных правках. Принятое обновление ждёт завершения или отмены активной тренировки; снимок уже начатой сессии и история не переписываются.
- Форматы `.rptinvite`, `.rptresult` и `.rptprogram` передаются через Android Sharesheet и FileProvider; максимальный размер зашифрованного пакета — 8 МБ. Входящий файл можно открыть из мессенджера или выбрать в настройках. Отправка не считается доставкой или импортом.
- Связь: разовый ECDH P-256, HKDF-HMAC-SHA256 и сравнение отпечатка (первые 80 бит SHA-256 от общего ключа) по независимому каналу. Приглашения истекают через 30 дней и одноразово применяются. Пакеты — AES-256-GCM с 12-байтным nonce, 128-битным тегом и сроком 30 дней; адресные метаданные включены в AAD.
- Поскольку Android Keystore поддерживает назначение ECDH только начиная с API 31, разовый P-256 приватный ключ приглашения шифруется ключом AES-GCM из Keystore при сохранении и очищается после ответа. Общий ключ каждой связи также хранится только в запечатанном виде.
- Повторные пакеты блокируются по ID; одинаковые тренировки — по ID события даже в новом пакете. Импорт результатов выполняется транзакционно и пересчитывает локальную аналитику.
- Telegram-доставка Stage 3 — отдельная опция. Для пересылки без VPS используется Cloudflare Worker + D1; бот требует однократной настройки и остаётся внешним сервисом. Дневник, локальный журнал и ручной обмен не зависят от Worker, базы, сети или Telegram.

## Stage 3 — полуавтоматическая доставка через Telegram

- Подопечный может при завершении тренировки выбрать «Завершить и отправить тренеру». Приложение создаёт `.rptdelivery` с читаемым PDF и отдельным адресным зашифрованным `.rptresult`, затем открывает стандартный Android Sharesheet. Пользователь выбирает Telegram-бота и подтверждает отправку.
- Тренер и подопечный отдельно подключают одну и ту же Stage 2 доверенную связь к боту, отправив `.rptrelay` из личного чата. Маршрут активируется после совпадения двух регистраций; для каждой стороны используется отдельный Telegram-чат.
- Бот направляет тренеру PDF с кратким уведомлением, затем зашифрованный файл импорта. Он также пересылает зашифрованный `.rptprogram` от тренера подопечному. Импорт и принятие программы всегда подтверждаются отдельно в приложении.
- Telegram и Worker могут читать PDF и метаданные доставки; `.rptresult` и `.rptprogram` остаются зашифрованными для RepTrack. Worker хранит в D1 только привязку Telegram-чатов, состояние повторной доставки и идентификаторы устройств/связей; содержимое файлов в D1 не сохраняется.
- Отзыв доверенной связи в приложении не отключает Worker автоматически. Если маршрут был подключён, отключи его командой `/disconnect ID` в чате бота; ID маршрута отображается рядом с отпечатком в настройках RepTrack. `/disconnect` без ID удаляет все маршруты этого Telegram-чата.
- Для развёртывания нужны бот, Cloudflare Worker и D1. Тарифы Free имеют жёсткие квоты и могут временно остановить доставку при превышении; Worker не гарантирует нулевые эксплуатационные расходы при смене тарифа или правил провайдера. Шаги и квоты указаны в [`../telegram-bot/README.md`](../telegram-bot/README.md).

## Сборка и проверки

Для сборки нужны JDK 17 или 21, Android SDK API 36 и Build Tools 36.0.0. Приложение использует minSdk 26, targetSdk 35; Gradle Wrapper закреплён на 8.11.1, Java/Kotlin bytecode target — 17.

В PowerShell из папки `android/`:

```powershell
$env:JAVA_HOME = '<путь к JDK 17 или 21>'
$env:ANDROID_HOME = '<путь к Android SDK>'
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug
```

Инструментальные сценарии требуют подключённого Android-эмулятора/устройства и запускаются отдельно от unit-тестов.

Для миграции SQLite и импорта/восстановления на подключённом эмуляторе:

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=app.reptrack.DiaryRepositoryInstrumentedTest
```

В debug APK открой верхнюю кнопку профиля и нажми «Создать / открыть тестовый профиль». Создаётся отдельный профиль подопечного с синтетическим циклом Push / Ноги / Pull / Up и тестовыми тренировками. Повторное открытие не дублирует записи; личная история не меняется. Рядом доступна загрузка двух синтетических demo-отчётов для проверки импорта. В release-сборке эти кнопки отсутствуют.

Для повторного создания того же набора на тестовом эмуляторе:

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=app.reptrack.ManualPreviewSeedTest
```

Инструментальный тест использует ту же фикстуру и проверяет, что записи остаются в отдельном профиле.

Debug APK после сборки: `app/build/outputs/apk/debug/app-debug.apk`. Подписанный release APK и публикация не настраивались.

## Текущий объём

Stage 1 и локальная часть Stage 2 реализованы в Android-приложении. Для Stage 3 подготовлены Telegram-сценарий и Cloudflare Worker; реальное развёртывание требует настройки аккаунтов и токена владельцем проекта. В проект не добавлена непроверенная база упражнений, анатомические изображения или инструкции по технике.
