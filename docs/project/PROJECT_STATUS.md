# RepTrack: итоги подготовки проекта

Дата: 17 ноября 2026. База изменений: `d6f8c4722b3f5282e3bfa7fec434d5af4b43551b`, ветка `main`.

## Текущее приложение

- Android — основной офлайн-дневник. Сборка использует только Android-исходники и ресурсы; Telegram relay и web-прототип самостоятельны.
- Каталог расширен до 123 упражнений: устойчивые ключи, синонимы, основные/дополнительные мышцы, положение, выполнение, дыхание, ошибки, ограничения и локальные изображения. Сводки используют основные мышцы фактического состава тренировки.
- Поиск и фильтр по мышцам заменили фильтры оборудования/проверенности. Карточку техники можно открыть также при выборе упражнений в план.
- Главная содержит обзор и прогресс; запуск/продолжение ведёт в «Зал». В верхней панели доступен «Обмен».
- Локальный профиль имеет устойчивый публичный UUID; роли: «Тренер» и «Самостоятельный». Автор результата сохраняется по профилю доверенной связи при переключении активного дневника.
- База мигрирует в v8; резервный архив v5 сохраняет роль и публичные ID, старые форматы читаются.
- `.rptsnapshot` хранит изолированные снимки тренировки/периода в приватном каталоге приложения; подключение не заменяет дневник. Полное восстановление резервной копии отделено и требует подтверждения.

Материалы сначала перенесены за пределы проекта в локальный каталог визуализаций владельца; они не публикуются повторно. Обычный коммит удаляет файлы из нового состояния ветки, но не переписывает прежнюю Git-историю и не уменьшает её автоматически.

В `.gitignore` добавлены локальные визуальные результаты, APK, логи проверок, временные handoff и локальные OmniRoute-эксперименты. Папка `UI/` с пользовательским исходным скриншотом исключена из новых публикаций; уже отслеживаемый исходный референс сохранён.

Удалены девять одноразовых `tasks/omniroute-*` сценариев/ответов, оставшихся от настройки и проб провайдеров. Рабочие вспомогательные инструменты в `tools/omniroute-fallback/` сохранены локально и исключены из публикации; они не нужны для сборки.

Сохранены используемые ресурсы `android/app/src/main`, Gradle Wrapper, конфигурация CI, исходные дизайн-концепты и их манифест происхождения. Каталог generated artwork содержит реальные офлайн-ресурсы приложения и не является кэшем. Служебный инструмент сравнения теперь требует явных входного/выходного каталогов вместо несуществующего старого прогона.

Текущая продуктовая спецификация `docs/tasks/gym-catalog-home-exchange.md`, шаблон ТЗ, план согласованной очистки личных данных и исследование мышечной карты сохранены как актуальные требования/основания. Старые ссылки на удалённые исторические пути в плане очистки являются перечнем согласованной операции, а не ссылками на текущие входные файлы.

## Ограничения

- Профиль локальный; ID помогает атрибуции и не служит удостоверением личности.
- Изображения иллюстративны и не заменяют текстовую инструкцию; специализированная внешняя проверка всех методик не заявляется.
- Живые Telegram Bot API, Worker/D1 не развёртывались и не проверялись этой задачей. Токены не нужны для офлайн-сборки.
- Web и dist сохранены как отдельный прототип; их внешний вид не подтверждает Android. Они имеют разные версии содержимого и не являются взаимозаменяемыми исходниками.
- Очистка завершённых материалов не означает удаление SDK, AVD или локальных пользовательских данных.
